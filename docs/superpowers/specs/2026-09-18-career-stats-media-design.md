# 設計書 — 就職・転職 統計データメディア(完全自動運用)

作成: 2026-09-18 / 作成者: 設計セッション(Claude) / 状態: 草案(調査結果の反映中)

## 0. 目的と優先順(BRIEF.md より)

1. **完全自動で運用できること**(最優先)。人が定期的に行う作業をゼロにする。人がやってよいのは「契約・認証など外部との手続き」と「通知を読むかどうか」だけ。
2. **マネタイズの最大化**。アフィリエイトに限定しない。

固定条件: SEO 主軸 / 領域は就職・転職 / 職業安定法・景表法(ステマ規制)遵守 / Google スパムポリシー(scaled content abuse 等)に抵触しない。

**両立しない場合は 1 を優先する。** 具体的には「収益が大きくても人の定期作業や届出・審査が継続的に必要なもの」は採用しない、または人待ちリストに出して依存しない部分だけ進める。

### 1.2 採用: A1「公的統計データメディア」

- サイト名(仮): **就活・転職データラボ**(命名は後から変更可能。URL 構造には含めない)
- ページ種別(初期。総ページ数は上限 300 に固定し、ゲートで監視):
  1. トップ(最新月のサマリ、全国値、注目の変化)
  2. 指標ページ(全国・時系列): 有効求人倍率 / 新規求人倍率 / 完全失業率 / 転職者数 など
  3. 都道府県ページ(47): その県の有効求人倍率の時系列、全国順位、前月比・前年同月比
  4. 職業別ページ: 職業分類別の有効求人倍率(公開されている大分類・中分類)
  5. 用語・出典・運営者情報・プライバシーポリシー・広告表記ページ(静的)
- 文章は **テンプレート+数値から機械的に導出できる記述のみ**(例: 「2026年7月の東京都の有効求人倍率は 1.85 倍で、前月比 +0.02、全国 3 位」)。生成 AI による自由記述は使わない(scaled content abuse 回避と事実性の担保)。
- 図表は **サーバ側で SVG を生成**して HTML に埋め込む(クライアント JS 不要、CDN 依存なし、決定的で差分テストが可能)。

## 2. 収益源の組み合わせ

### 2.1 評価表(BRIEF の要求: 自動運用との両立 / 法令上の制約 / 立ち上がり時期)

| 収益源 | 自動運用と両立するか | 法令上の制約 | 立ち上がり時期 | 判定 |
|---|---|---|---|---|
| **R1 アフィリエイト(A8: 新卒就職エージェントneo=提携済み / お仕事ラボ=未提携)** | ◎ リンク挿入・PR 表記・リンク死活監視をすべて自動化できる。提携申請だけ人 | 景表法ステマ規制: ページ上部に「本ページにはプロモーションが含まれます」を自動挿入。ASP 規約の表記要件。職業安定法: エージェント LP へのリンクは求人情報の提供ではない(§4) | 即時掲載可。成果は SEO 流入後(3〜6 か月) | **採用(第1段階)** |
| **R2 ディスプレイ広告(Google AdSense)** | ○ 承認後は Auto ads で自動。申請・承認・支払設定は人 | AdSense プログラムポリシー(自動生成コンテンツの制限→本サイトは一次統計の加工で価値があるがリスクは残る)。独自ドメインが事実上必要 | 独自ドメイン+承認後。流入前は収益ゼロ | **採用(人待ち: ドメイン・アカウント)** |
| **R3 有料データ/レポート販売(Stripe Payment Link / 月次 CSV・PDF)** | ○ 商品(月次データセット)生成と決済リンク掲載は自動化可能。Stripe 契約と特商法表記の確定は人 | 特定商取引法に基づく表記(法人名・住所・電話・返品規定)が必須。インボイス | 需要が不確実。流入が出てから | **採用(第2段階、人待ち: Stripe・特商法表記)** |
| R4 直接契約・スポンサー | △ 交渉は人。自動化できるのは「お問い合わせ導線」と「メディアキット(PV・掲載指標)の自動生成」まで | 景表法(タイアップ表記) | 流入が十分になってから | 導線のみ実装、契約は人 |
| R5 サイト売却 | △ 出口戦略。自動化できるのは指標の継続記録のみ | — | 12 か月以上先 | 撤退・出口基準として記載(§8) |
| R6 データ API 提供 | ○ R3 と同じ仕組みで自動化可能 | 政府統計の再配布は出典表記があれば可 | R3 と同時期 | R3 に統合 |

### 2.2 採用構成と段階

- **第1段階(今回実装)**: R1。提携済みの「新卒就職エージェントneo」を、新卒関連ページ(内定率・新卒離職率・都道府県ページの新卒向け導線)に文脈一致で掲載。提携条件(対象地域: 東京/神奈川/千葉/埼玉/大阪/京都/兵庫、対象: 26/27 卒)に合わせ、**対象地域のページにのみ**表示する(確定率を下げる無関係表示を避ける)。
- **第2段階(人待ち解消後に自動で有効化)**: R2 AdSense(設定ファイルに publisher ID を置けばビルド時に自動挿入)、R1 お仕事ラボ(提携承認後に設定ファイルへ追加)。
- **第3段階**: R3 データ販売(Stripe Payment Link の URL を設定ファイルに置けば自動掲載)。
- 収益源はすべて **設定ファイル(`config/monetization.json`)の allowlist** で管理し、ゲートが「allowlist にないアフィリエイト URL」「PR 表記のないアフィリエイトページ」をブロックする。

### 3.1 比較した案(ホスティング + スケジューラ)

| 案 | 人待ちなしで今すぐ動くか | 定期実行 | 費用 | 備考 | 判定 |

### 3.2 比較した案(静的サイト生成)

| 案 | 判定理由 |
|---|---|
| **手書き TypeScript テンプレート(依存なし)** | 出力が決定的で、ゲートとテストを同じ言語で書ける。ページ種別が 5 つしかなく SSG フレームワークの学習・依存コストに見合わない。**採用** |
| Astro / Eleventy | 柔軟だがビルドがブラックボックス化し、ゲートが HTML 出力に対する後付け検査になる。将来ページ種別が増えたら再検討 |
| 図表: Chart.js(クライアント) | CDN 依存・JS 必須・スナップショットテスト不可 → 不採用 |
| 図表: Python matplotlib で PNG | Actions で Python 環境が増える。PNG は alt テキスト以外に検索エンジンが読めない → 不採用 |
| **図表: サーバ側 SVG 生成** | 依存なし、決定的、HTML 内テキストとして数値が残る。**採用** |

### 3.3 データ取得

- 一次データは e-Stat のファイルダウンロード URL(appId 不要)または各省庁の公開ファイル(CSV/Excel)。詳細と規約確認は `docs/data-sources.md`。
- e-Stat API(appId 必要)は人待ち。**appId が無くても動く経路を主経路にする**(目的1優先)。
- 取得したファイルは `data/raw/` にハッシュ付きで保存し、パース結果を `data/normalized/*.json` に保存してリポジトリにコミットする(再現性と差分検知)。

### 3.4 コンポーネント(1 ユニット 1 責務)

```
src/
  sources/        取得元ごとのアダプタ(URL 解決・ダウンロード・パース → 正規化 JSON)
  normalize/      正規化スキーマ(指標 × 地域 × 期間)と型
  gates/          公開ゲート(データ異常 / 出典死活 / 法令表記 / 品質 / リンク)
  render/         HTML テンプレート・SVG 図表・sitemap・robots
  monetize/       allowlist に基づくアフィリエイト・広告・決済リンクの挿入
  cli/            collect / check / build / cycle(collect→check→build)
config/
  sources.json    取得元定義(URL、期待列、更新周期)
  monetization.json  収益源 allowlist(状態: active / pending)
  site.json       サイト名・URL・運営者情報
data/
  raw/ normalized/  取得結果(コミット対象)
site/             ビルド出力(Pages へデプロイ)
```

データフロー: `collect`(取得・正規化) → `check`(ゲート。1 つでも FAIL なら終了コード 1 でデプロイしない) → `build`(HTML/SVG 生成) → Actions が `site/` を Pages へデプロイ。

### 3.5 スケジュール(GitHub Actions)

| ワークフロー | トリガ | 内容 |
|---|---|---|
| `cycle.yml` | 週 1 回(火曜 03:00 UTC = 12:00 JST)+ 手動 | collect → check → build → deploy。データ更新が無ければ同一内容を再デプロイ(冪等) |
| `healthcheck.yml` | 毎日 | 公開 URL の 200 確認、アフィリエイト先・出典 URL の死活。失敗時は Issue を自動作成 |
| `ci.yml` | push / PR | test + lint |

厚労省の一般職業紹介状況は原則「翌月末の火曜〜金曜 8:30 JST」に公表されるため、週 1 回の実行で最大 1 週間の遅延に収まる。

## 6. テスト方針

- TDD(vitest)。各ユニットは純粋関数中心にし、ネットワーク I/O は `fetch` 注入で差し替える。
- fixtures: 取得元ファイルの小さな実サンプル(数行)を `tests/fixtures/` に置き、パーサはそれで検証。
- ゲートは「通る fixture」と「落ちる fixture」を必ず対で持つ。
- lint: eslint + `tsc --noEmit`。CI で test/lint が終了コード 0。

## 8. 撤退基準(数値)

(HANDOFF.md にも転記)
- 公開後 6 か月時点で Search Console の月間クリックが 300 未満、かつ 9 か月時点で 1,000 未満なら、コンテンツ投資を止め維持モード(データ更新のみ)へ。
- 12 か月時点で月間収益が 5,000 円未満(全収益源合計)なら、サイト売却または閉鎖を検討(R5)。
- 連続 3 サイクルでゲート G2(出典死活)が FAIL し続けた場合は、取得元の構造変更とみなし人待ちリストへ。
